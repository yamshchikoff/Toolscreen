# Отладка Minecraft при помощи GDB

## Главное правило

**Отладка через GDB означает действия посредством GDB, а не написание кода.** Если программа падает — нужно аттачиться, ставить брикпинты, смотреть состояние. Не комментировать код чтобы «проверить гипотезу». Все проверки — через GDB.

## gdbwrap — интерактивная обёртка

`scripts/gdbwrap` — Python-скрипт через pexpect, позволяет управлять GDB из bash.

**Команды**:
- `python3 scripts/gdbwrap attach <pid>` — аттач, сохраняет сессию в `/tmp/gdbwrap/session`
- `python3 scripts/gdbwrap cmd <gdb-command>` — выполнить команду, вернуть вывод
- `python3 scripts/gdbwrap detach` — detach и закрыть

**Порядок работы**:
1. Попросить пользователя зайти в мир
2. **Сначала** `gdbwrap attach <pid>` (до инжекта)
3. Потом `sudo ./scripts/inject.sh`
4. Через `gdbwrap cmd` ставить брикпинты, продолжать выполнение
5. После краша — `gdbwrap cmd "bt"`, `gdbwrap cmd "info registers"` и т.д.

## Важно: протокол взаимодействия

1. GDB аттачится к процессу Minecraft **только после** того как пользователь зашёл в мир.
2. Перед аттачем нужно **попросить** пользователя перезапустить игру и зайти в мир.
3. gdbwrap запускается **до** инжекта.

## Особенности

- `echo "rabbit chess" | sudo -S` — передача пароля в sudo
- JVM генерит внутренние SIGSEGV в `Parker::park()` — это не краш игры
- Не использовать `printf` с экранированием в gdb — битые форматы
