# Требования к обёртке над GDB

## Цель

Обеспечить интерактивную отладку Minecraft через GDB из CLI-инструментов Claude (Bash).

## Функциональные требования

1. **Персистентная сессия**: GDB запускается один раз и остаётся живым между командами.
2. **Интерактивность**: возможность выполнять любые команды GDB в любой момент, не перезапуская сессию.
3. **PTY**: GDB должен работать через псевдотерминал (pexpect), а не через PIPE (stdin/stdout).
4. **Сохранение состояния**: брикпинты, watchpoint'ы, переменные сохраняются между командами.
5. **Асинхронность**: команды посылаются из одного Bash-вызова, результат читается в другом.
6. **Неблокирующий запуск**: `start` возвращает управление сразу после запуска сервера.

## Команды

```
gdbwrap start <pid>    — аттач, запуск GDB в фоне
gdbwrap cmd <command>  — выполнить команду, получить вывод
gdbwrap stop           — detach + quit
```

## Механизм

- `start` запускает GDB через pexpect (PTY), входит в главный цикл опроса командного файла
- `cmd` пишет команду в файл, ждёт файл-флаг готовности, читает файл-вывод
- `stop` посылает `detach`/`quit`, убивает GDB

## Нефункциональные требования

- Не использовать pickle (pexpect.spawn не сериализуем)
- Не зависеть от сетевых портов
- Работать через файловую систему (командный файл + файл вывода + файл-флаг)
- Таймаут команд — не более 10 секунд
