# Подходы к перехвату клавиатуры на Linux

> Обратная ссылка: [CLAUDE.md](../CLAUDE.md)

## Журнал подходов

| # | Подход | Механизм | Статус | Причина отказа / Результат |

## Подход 1: PULL — XCheckMaskEvent

**Суть**: открываем свой X11-дисплей, вешаем `XSelectInput` на окно игры, поллим `XCheckMaskEvent` каждый кадр в `hk_glXSwapBuffers`.

**Коммиты**: `272debb` (hotkey_detect), `8fca1c2` (debug all keys), `0cf85b1` (filter fix)

**Почему не работает**: X11 доставляет события на все дисплейные соединения, выбравшие ввод на окне. Но LWJGL/GLFW на своём потоке вызывает `XNextEvent` (блокирующий) и забирает события из очереди X-сервера раньше, чем наш неблокирующий `XCheckMaskEvent` успевает их увидеть. К моменту нашего полла очередь пуста.

**Урок**: PULL-поллинг в конце кадра несовместим с PUSH-чтением игры в начале кадра.

## Подход 2: PUSH — XNextEvent LD_PRELOAD interposer

**Суть**: экспортировать `XNextEvent` из `libtoolscreen.so` с `extern "C"`, чтобы динамический линкер подменил им системный `XNextEvent`. В нашем обработчике — вызвать настоящий, инспектировать событие, положить в очередь.

**Коммиты**: `da0c8c3` (XNextEvent hook), `2db6d0d` (`__attribute__((used))` fix)

**Почему не работает**: инжектор (`scripts/inject.sh`) делает `gdb dlopen("libtoolscreen.so")`, а не `LD_PRELOAD`. `dlopen` загружает .so в адресное пространство, но не подменяет символы других библиотек. `LD_PRELOAD` обрабатывается динамическим линкером на старте процесса и не может быть применён постфактум. Символ `XNextEvent` присутствует в `.dynsym` (проверено `nm -D`), но никогда не вызывается.

**Урок**: LD_PRELOAD-interposition и gdb-dlopen-инжектор — несовместимы. GL-хуки работают не через interposition, а через прямой патч dispatch-таблицы libGL (data-only).

## Подход 3: PUSH — inline-хук XNextEvent (запланирован)

**Суть**: использовать существующий движок инлайн-хуков (`InstallJump`/`WriteRelJump`/`AllocateNear` в `glx_hook.cpp`) для патча первых 5 байт `XNextEvent` в libX11.so на jump в наш обработчик. Патч делать в конструкторе (gdb морозит все потоки → mprotect безопасен).

**План**:
1. `dlsym(RTLD_DEFAULT, "XNextEvent")` → адрес в libX11.so
2. `WriteRelJump(target, hk_XNextEvent, backup)` — 5-байтовый атомарный jmp rel32
3. Если расстояние >2GB → bridge-страница через `AllocateNear()`
4. Трамплин: backup-байты + jmp target+5 для вызова оригинала

**Риски**:
- Расстояние между .so и libX11 может быть >2GB — нужен bridge
- Inline-хуки на код в рантайме — TLB shootdown может задеть другие потоки (но в конструкторе gdb морозит все)
- Нет dispatch-таблицы как у GLX — это именно патч кода
